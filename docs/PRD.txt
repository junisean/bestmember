4. 첫 페이지와 배치

5. 인재상 선택
왼쪽 첫 구역 제목은 ‘1. 인재상 선택’이다. ‘최대 3개까지 선택할 수 있어요.’와 현재 선택 수 / 3을 표시한다.
30개 인재상을 모두 선택 가능한 버튼으로 제시한다. 인재상은 1~3개를 선택한다. 선택된 항목은 체크표시와 파란색 선택 상태로 표시한다.
3개를 선택하면 선택하지 않은 항목을 추가로 선택할 수 없다. 기존 선택 해제는 가능해야 한다.
선택을 해제한 인재상에 속한 선택 문항도 함께 제거한다. 남은 인재상과 직접 질문은 유지한다. 활성 탭을 해제했을 때는 남아 있는 첫 인재상을 활성화하고, 모두 해제하면 초기 안내를 표시한다.

6. 기본 질문 선택
왼쪽 두 번째 제목은 ‘2. 질문 선택’이다. ‘선택한 인재상의 질문을 합쳐서 총 10개를 골라주세요.’를 표시한다.
중요: 인재상마다 10개가 아니다. 선택한 최대 3개 인재상을 모두 합쳐 기본 질문 정확히 10개다. 한 인재상에서 10개를 고르거나 4+3+3, 2+4+4 등의 조합을 허용한다. 선택한 인재상 중 문항이 0개인 항목이 있어도 전체가 10개면 생성 가능하다.
선택한 인재상별 탭을 표시한다. 탭에는 인재상 이름과 해당 인재상에서 선택한 개수를 표시한다.
활성 탭의 전체 30문항을 체크박스와 함께 보여준다. 각 문항에는 유형과 원본 번호를 표시한다. 유형은 실제 경험, 상황 대응, 업무 태도다.
체크하면 즉시 오른쪽에 반영되고 체크 해제하면 제거된다. 탭을 바꿔도 선택 상태가 유지된다.
전체 10개에 도달하면 모든 인재상의 미선택 체크박스를 비활성화한다. 이미 선택한 체크박스는 해제 가능하다. 하나를 해제하면 미선택 항목을 다시 고를 수 있다. 이벤트 단계에서도 11번째 기본 질문 선택을 방지한다.
기본 질문의 선택 수와 남은 개수를 표시한다. 인재상이 없으면 먼저 인재상을 선택하라는 안내를 보여준다. 아무 문항도 선택하지 않은 상태에서 임의의 질문을 자동 선택하지 않는다.

7. 사장님 직접 질문
왼쪽 하단 제목은 ‘3. 직접 질문 추가’다. 안내 문구는 ‘사장님이 더 묻고 싶은 내용을 넣어주세요.’다.
‘추가할 질문’ 레이블, 여러 줄 입력란, ‘질문 추가’ 버튼을 둔다. 예시 플레이스홀더는 ‘예: 우리 매장에서 일하며 배우고 싶은 것은 무엇인가요?’다.
공백만 입력한 질문은 추가하지 않고 입력을 요청한다. 질문 하나는 최대 500자다. 직접 질문은 최대 20개다. 초과 시 구체적인 안내를 표시한다.
추가하면 입력란을 비우고 추가 목록과 오른쪽 미리보기에 즉시 반영한다. 직접 질문별 ‘삭제’ 버튼이 있어야 한다.
직접 질문은 기본 질문 10개와 별도로 계산한다. 따라서 최종 설문은 기본 10개와 직접 질문 0~20개로 구성된다. 직접 질문만 넣고 기본 질문 없이 링크를 만드는 기능은 현재 범위에 없다.
직접 질문은 기본 질문 그룹 뒤 ‘추가 질문’ 그룹에 입력 순서대로 배치한다. 추가·삭제는 링크 생성 결과에도 반영된다.

8. 오른쪽 미리보기
상단에 ‘설문지 미리보기’, 전체 문항 수, ‘설문 링크 만들기’ 버튼, 선택 진행 안내를 둔다.
전체 문항 수는 현재 고른 기본 질문과 직접 질문을 합한 수다. 기본 질문이 정확히 10개이고 인재상이 하나 이상일 때만 링크 생성 버튼을 활성화한다.
내부는 흰 설문지 형태다. 제목은 ‘외식업 신규 채용 설문지’다. 안내 문구는 ‘정답은 없어요. 본인의 경험과 생각을 편하게 적어주세요.’다.
선택 문항은 인재상 그룹별로 표시한다. 그룹 제목에 인재상과 문항 수를 표시한다. 그룹 순서는 인재상 선택 순서다. 그룹 내부 질문은 원본 문항 번호 오름차순이다. 0문항 그룹은 설문지에 표시하지 않는다.
질문은 설문 전체에서 1번부터 연속 번호를 부여한다. 각 질문 바로 아래 여러 줄 답변 입력란을 둔다. 답변 플레이스홀더는 ‘답변을 입력해 주세요’다.
질문이 없으면 ‘질문을 고르면 설문지가 완성돼요’와 사용 안내를 표시한다. 편집 중 미리보기 입력 내용과 지원자의 최종 서버 제출은 별개다.

9. 링크 생성
‘설문 링크 만들기’를 누르면 현재 선택 내용의 스냅샷으로 전용 주소를 만든다. 생성 이후 사장님의 편집 상태가 바뀌어도 기존 주소의 문항은 바뀌지 않아야 한다.
대화상자 제목은 ‘설문 링크를 만들었어요’다. 주소 입력란, ‘링크 복사’, ‘설문지 열기’, ‘닫기’를 제공한다.
복사 성공 피드백을 표시한다. 클립보드 권한 등으로 실패하면 주소를 선택해 수동 복사할 수 있게 안내한다. ‘설문지 열기’는 새 탭으로 연다.
현재 주소 형식은 /#survey= 뒤에 URL 안전한 Base64 JSON을 붙이는 방식이다. 페이로드 버전 v=1, selected, chosen, custom을 보존한다. selected는 인재상 배열 인덱스, chosen은 인재상별 문항 배열 인덱스다. 인덱스는 0부터 시작한다.
생성된 주소로 접속하면 지원자 전용 모드로 렌더링한다. 주소가 잘리거나 데이터 형식·선택 개수·문항 인덱스가 올바르지 않으면 잘못된 설문 링크 안내를 표시한다.
제작 중 선택 내용은 해당 브라우저에 저장해 재방문 시 복구한다. 기존 저장 내용이 기본 질문 10개 제한을 넘으면 10개 이하로 정리한다.

10. 지원자 전용 설문
지원자는 링크를 열어 설문 제목, 안내, 본인 정보, 질문과 답변란, 제출 버튼을 본다. 편집용 좌측 화면이나 제작 버튼은 보이지 않는다.
설문 맨 위에 ‘지원자 정보’ 구역을 둔다. 이름, 생년월일, 전화번호는 모두 필수다.
이름은 앞뒤 공백을 제거하고 60자 이내의 비어 있지 않은 문자열로 검증한다. 생년월일은 날짜 입력 컨트롤을 사용하며 YYYY-MM-DD 형식의 실제 존재하는 날짜여야 하고 미래일 수 없다. 전화번호는 전화 입력 컨트롤과 예시 010-1234-5678을 제공한다. 입력은 최대 25자이며 저장 검증 시 공백·괄호·하이픈을 제거한 숫자 9~15자리인지 확인한다.
선택된 모든 질문에 답변 입력란을 제공한다. 각 답변은 필수이며 공백만 있는 답변은 허용하지 않는다. 답변은 문항당 최대 5,000자다. 질문 문구와 답변의 줄바꿈을 보존한다.
답변은 현재 탭에 임시 저장한다. 서버 제출이 끝나면 해당 설문의 임시 답변을 정리한다. 이름·생년월일·전화번호와 답변이 채용 담당자 확인을 위해 서버에 저장된다는 안내를 제출 버튼 앞에 표시한다.

11. 제출과 서버 저장
하단에 ‘제출하기’를 둔다. 입력 검증을 통과하면 서버에 지원자 정보와 문항별 답변을 전송한다.
저장 중 버튼을 비활성화하고 진행 안내를 표시한다. 성공 응답을 받은 뒤에만 폼을 완료 화면으로 교체한다. 완료 제목은 ‘제출이 완료됐어요’이고 본문은 ‘지원자 정보와 답변이 담당자에게 전달됐어요.’다.
네트워크·서버·검증 오류가 생기면 입력을 유지하고 원인을 설명하며 다시 제출할 수 있도록 버튼을 복구한다. 실패를 성공으로 처리하지 않는다.
동일한 제출 시도의 중복 요청은 한 건으로 처리한다. 제출 ID를 생성해 재시도에 재사용하고 서버 저장 시 같은 ID의 기존 지원서를 덮어쓰지 않는다.
서버는 설문 데이터와 기본 질문 총 10개 규칙, 인재상 최대 3개, 인덱스 유효성·중복, 직접 질문 최대 20개·500자, 지원자 정보, 답변 유무·길이를 재검증한다. 기본 질문의 실제 문구는 서버 문항 원본에서 가져온다.
제출 요청은 동일 출처와 JSON 형식을 검사하고 본문 크기를 제한한다. 현재 본문 상한은 250,000자 수준이다.
응답은 브라우저 저장이 아닌 서버 영속 저장소에 보관한다. 현재 구현은 Cloudflare R2의 BUCKET 바인딩을 사용한다.
저장 레코드: id, name, birth, phone, questions, submittedAt. questions의 각 항목: key, trait, question, answer. 제출 시각은 서버에서 생성한다. 저장 경로는 submissions/{id}.json이다.

12. 관리자 응답 확인
첫 페이지 오른쪽 위 ‘지원자 응답 확인’을 누르면 /admin으로 이동한다.
비로그인 또는 관리자 외 계정은 지원자 내용을 볼 수 없다. 로그인 안내와 사장님 계정 로그인 진입점을 제공한다. 로그인 여부와 관리 권한은 구별한다.
관리 화면은 ‘설문 만들기’ 복귀 링크, ‘제출된 답변’ 제목, 사장님 전용 안내, 지원자 목록, 더 보기, 상태 메시지로 구성된다.
지원자 목록의 각 행에는 이름, 제출 일시, 확인 상태를 표시한다. 제출 일시는 Asia/Seoul 기준 한국어 날짜·시간으로 표시한다.
지원자를 선택해 펼치면 생년월일·전화번호와 모든 질문·답변을 확인할 수 있다. 직접 질문과 답변도 포함한다. 입력 내용은 HTML로 실행하지 않고 텍스트로 출력한다.
펼쳐 실제 내용을 열 때 서버에 확인 상태를 저장한다. 저장 성공 후 ‘미확인’을 ‘확인함’으로 바꾼다. 실패하면 오류를 표시하고 다시 펼쳐 재시도할 수 있게 한다. 단순히 목록을 불러왔다는 이유로 전체를 확인 처리하지 않는다.
확인 기록은 reviewed/{id}.json에 reviewedAt으로 따로 보관한다. 지원자가 제출한 원본 내용은 확인 처리로 변경하지 않는다. 새로고침하거나 다른 기기에서 열어도 확인 상태가 유지된다.
목록은 페이지당 20건 단위로 불러오고 커서가 있으면 ‘더 보기’를 표시한다. 응답이 없으면 아직 제출된 답변이 없다는 안내를 제공한다. 로딩, 조회 실패, 확인 상태 저장 실패를 각각 표시한다.
미확인 건수는 제출된 응답 중 확인 기록이 없는 건수다. 목록의 일부 페이지만 기준으로 계산하지 않는다. 집계 API도 관리자 권한으로 보호한다.

13. 서버 인터페이스와 권한
POST /api/submissions: 지원서 제출. JSON 본문은 id, survey, name, birth, phone, answers다. survey는 설문 페이로드이며 answers는 문항 key와 답변 문자열의 사전이다. 성공은 {ok:true}다.
GET /api/submissions?cursor=...: 관리자 목록. items와 다음 cursor를 반환한다. 각 레코드에 reviewed 상태를 포함한다.
GET /api/submissions/summary: 관리자용 {unread:N} 반환.
PATCH /api/submissions/{id}: 관리자 전용 확인 처리. 동일 출처 요청만 허용하고 존재하는 제출 ID인지 검사한다.
GET /admin: 관리자 화면. 서버에서 인증·인가한다.
응답 관련 API는 캐시하지 않는다. 익명 또는 권한 없는 조회·상태 변경은 403을 반환한다. 유효하지 않은 입력은 400, 없는 응답은 404, 지원하지 않는 메서드는 405, 지나치게 큰 요청은 413, 저장 장애는 503 등 구분 가능한 오류를 반환한다.
공개 접속이 응답 데이터 공개를 의미해서는 안 된다. 공개 전환 후에도 응답 조회와 확인 상태 변경의 관리자 보호는 유지한다.

14. 현재 배포와 소스 구성
기존 Sites 프로젝트와 저장 자료를 유지한다. 프로젝트 ID: appgprj_6aeb524514dc8191a125aa278a3df937.
현재는 공개 접근으로 변경 완료됐다. 단축 주소 https://is.gd/bestmember는 운영 첫 페이지로 연결된다. 단축 주소를 임의로 다른 사이트로 바꾸지 않는다.
소스의 worker/index.js는 요청 처리와 관리자 화면, worker/content.js는 제작 화면과 전체 질문 데이터다. build.mjs가 dist/server/index.js와 dist/.openai/hosting.json을 생성한다.
.openai/hosting.json에는 해당 project_id와 r2:BUCKET, d1:null을 선언한다. 서버 기능이 있으므로 static 전용 설정으로 되돌리지 않는다. 소스·아카이브·배포 버전을 일치시킨다.
첨부 자료에는 운영 자격 증명이나 비밀 토큰을 넣지 않는다. 다른 환경에 재구축할 때 해당 플랫폼의 정상적인 서버 인증 기능을 연결한다.

15. 상태와 예외 처리
인재상 없음: 먼저 인재상을 선택하라는 안내.
문항 없음: 미리보기 안내.
인재상 3개: 추가 선택 차단, 해제 허용.
기본 질문 10개: 미선택 문항 차단, 체크 해제 허용.
기본 질문 10개 미만: 링크 생성 차단, 남은 수 표시.
직접 질문 공백·길이·개수 초과: 입력 주변 또는 상태 영역에 이유 안내.
잘못된 설문 주소: 링크 재확인 안내, 잘못된 내용을 정상 설문으로 처리하지 않음.
지원자 필수 입력 누락·잘못된 날짜·전화번호·공백 답변: 제출 차단 및 수정 안내.
제출 중: 중복 클릭 차단, 저장 진행 표시.
제출 실패: 입력 유지, 재시도 가능.
제출 성공: 완료 화면.
관리자 권한 없음: 응답 비노출, 로그인 안내.
응답 목록 없음·조회 중·조회 실패·확인 기록 실패: 각 상태를 구별.

16. 완료 검증 항목
30개 인재상과 총 900문항, 섹션별 번호 1~30 및 유형 분류가 원본과 같다.
3개 초과 인재상과 총 11개 이상의 기본 질문을 선택할 수 없다.
여러 인재상에 걸쳐 정확히 10개를 고르면 링크가 활성화된다.
탭 변경·체크 해제·인재상 해제 후 개수와 미리보기가 일치한다.
직접 질문 추가·삭제·500자·20개 제한과 총 문항 수가 일치한다.
링크를 다른 브라우저에서 열어도 같은 문항과 순서가 복원된다.
지원자는 제작·관리 UI를 보지 않고 정보 입력과 답변·제출만 한다.
모든 필수 정보와 답변을 검증하고 서버에 저장한다.
중복 요청으로 기존 제출 내용이 덮어써지거나 중복 지원서가 생성되지 않는다.
실제 저장에 실패하면 완료 화면을 표시하지 않는다.
관리자만 원본 정보·질문·답변을 조회한다.
실제 답변을 펼칠 때만 확인 상태가 저장되고 미확인 집계가 갱신된다.
확인 상태와 답변은 새로고침 후에도 남는다.
긴 답변과 HTML처럼 보이는 입력이 안전하게 텍스트로 표시된다.
비로그인 첫 페이지·전용 설문 접속이 가능하고 비로그인 응답 API는 차단된다.
데스크톱 좌우 구성과 모바일 상하 구성이 읽기 쉽고 조작 가능하다.
단축 주소의 이동 대상이 실제 운영 첫 페이지와 같다.

17. 기능 범위 경계
현재 재현 대상에는 자동 채점, 합격·불합격 판단, 지원자 점수, 객관식 문항, 문자·이메일 자동 발송, 지원서 다운로드, 지원서 삭제, 응답 수정, 지원자 검색·필터, 여러 사장님의 독립 계정·매장 관리, 질문 순서 드래그 변경이 없다. 이런 기능으로 기존 필수 기능을 대체하거나 현재 존재한다고 표시하지 않는다. 추가 개발 시 별도 요구사항으로 정의한다.

첨부된 ‘외식업_채용설문_PRD.txt’, ‘외식업_신규채용_주관식질문_900개.md’, ‘현재소스’ 폴더와 화면 시안을 기준으로 외식업 채용 설문 제작 및 지원자 응답 관리 서비스를 완성해줘.

목표는 기존 결과물의 전체 기능과 동작을 그대로 재현하는 것이다. 기능을 요약하거나 생략하지 마. 일부 문항만 있는 샘플, 저장이 안 되는 화면 시안, 버튼만 있는 데모로 끝내지 마. PRD를 전체 계약으로 취급하고 이 프롬프트에 다시 적지 않은 세부사항도 모두 구현해.

진행 방법
1. 먼저 첨부 PRD 전체와 원본 문항 파일, 현재 소스의 요청 처리·문항 데이터·화면 구조·빌드 설정을 읽어.
2. 같은 환경에서 작업하면 기존 프로젝트·운영 주소·저장소·지원자 데이터를 보존해. 다른 환경이면 그 환경의 서버 영속 저장·정상 인증·배포 기능으로 동등하게 구현해. 비밀 토큰은 요구하거나 코드에 넣지 마.
3. 기존 기능을 실제로 작동하도록 구현하고 화면과 서버 권한을 함께 검증해.
4. 빌드·기능 검사·배포를 마친 뒤 접속 주소와 검증 결과를 알려줘. 미완료 기능이나 환경상 확인하지 못한 부분을 완료했다고 말하지 마.

화면과 디자인
첫 페이지 헤더의 왼쪽에는 ‘채용 설문지 만들기’, 보조 문구 ‘우리 매장에 맞는 질문을 골라보세요’를 넣어. 오른쪽 맨 끝에는 ‘지원자 응답 확인’ 버튼과 미확인 N건 배지를 넣어. 0건이면 배지를 숨겨.
데스크톱에서는 왼쪽 제작, 오른쪽 실시간 설문 미리보기로 나눠. 모바일에서는 위아래로 배치해. 흰 배경과 옅은 회청색 작업 영역, 남색 본문, 파란 강조색, 읽기 편한 한글 글꼴과 줄 간격, 명확한 선택·비활성·포커스 표시를 유지해. 첨부 시안과 현재 소스를 기준으로 하고 임의의 랜딩페이지나 대시보드 디자인으로 바꾸지 마.

질문 데이터
첨부된 Markdown의 30개 인재상과 각 30문항, 총 900개를 모두 그대로 써. 1~10은 실제 경험, 11~20은 상황 대응, 21~30은 업무 태도야. 질문을 다시 생성하거나 문구를 축약하지 마. 데이터 순서와 인덱스를 유지해.
30개 인재상은 성실함, 책임감, 정직함, 근태 준수, 신뢰성, 학습 능력, 업무 이해력, 업무 정확성, 업무 속도, 우선순위 판단, 멀티태스킹, 문제 해결력, 협동심, 의사소통 능력, 배려심, 피드백 수용성, 갈등 해결 능력, 친절함, 공감 능력, 감정 조절 능력, 서비스 감각, 위생 관념, 청결 유지, 안전 의식, 규정 준수, 적응력, 유연성, 자기주도성, 개선 의지, 장기근속 의향이야.

제작 기능
인재상은 최대 3개까지 골라. 선택하면 체크표시와 파란 선택 상태를 보여줘. 선택한 인재상마다 탭을 만들고 각 탭에 30문항과 유형·원본 번호·체크박스를 보여줘.
가장 중요한 제한: 인재상 각각 10개가 아니라 선택한 인재상 전체를 합쳐 기본 질문 정확히 10개야. 4+3+3이나 10+0+0도 가능해. 전체 10개가 되면 미선택 항목은 막고 기존 체크 해제는 허용해. 탭을 바꿔도 선택은 유지해. 인재상을 해제하면 그 인재상의 선택 문항을 제거해.
하단 ‘직접 질문 추가’에 여러 줄 입력란과 추가 버튼을 넣어. 빈 질문은 금지, 질문당 최대 500자, 최대 20개야. 추가 목록에 삭제 버튼을 제공해. 직접 질문은 기본 10개와 별도로 붙여. 추가·삭제 시 미리보기와 총 문항 수에 즉시 반영해.
오른쪽에는 제목·안내·인재상별 질문·질문 바로 아래 답변 입력란을 보여줘. 인재상은 선택 순서, 그 안의 질문은 원본 번호 오름차순, 직접 질문은 마지막 그룹에 입력 순서대로 배치해. 질문 번호는 전체에서 연속으로 매겨. 0문항 그룹은 숨겨. 빈 상태, 남은 선택 수, 완료 상태를 안내해.
기본 문항 10개를 골랐을 때만 링크 만들기를 활성화해. 링크 대화상자에는 주소, 복사, 설문지 열기, 닫기를 넣어. 클립보드 실패 시 수동 복사 안내도 구현해. 생성된 설문 내용은 이후 제작 화면을 바꿔도 그대로 유지돼야 해.
제작 선택은 브라우저에서 복구할 수 있게 저장해. 다만 제출된 지원서와 확인 상태는 반드시 서버에 저장해.

지원자 화면
설문 전용 링크로 열면 왼쪽 제작 화면과 제작 헤더·관리 버튼·링크 생성 버튼을 모두 숨겨. 질문과 응답을 위한 설문만 보여줘. 잘못된 링크는 오류 안내로 처리해.
설문 맨 위에 이름, 생년월일, 전화번호 필수 입력란을 넣어. 이름 60자, 실제 존재하고 미래가 아닌 생년월일, 전화번호 입력 최대 25자 및 정규화 후 숫자 9~15자리 검증을 구현해.
모든 문항에 여러 줄 필수 답변 입력란을 제공하고 문항당 최대 5,000자로 제한해. 공백만 있는 답변은 허용하지 마. 해당 탭의 답변 임시 저장을 지원해.
입력 정보와 답변이 담당자 확인을 위해 서버에 저장된다는 안내를 보여줘. 하단에 ‘제출하기’를 둬. 저장 중 버튼을 비활성화하고, 서버 성공 뒤에만 ‘제출이 완료됐어요’를 보여줘. 실패하면 입력을 유지하고 구체적인 오류와 재시도 기회를 줘. 같은 제출 ID의 중복 요청은 한 건만 저장하고 기존 데이터를 덮어쓰지 마.

서버와 관리자 기능
현재 서버는 Cloudflare Worker와 R2 BUCKET을 사용해. submissions/{id}.json에 id, name, birth, phone, questions, submittedAt을 저장해. questions에는 key, trait, question, answer를 포함해. 기본 문항 문구는 서버의 원본 데이터로 복원하고 모든 제한을 서버에서도 재검증해.
사장님 계정은 현재 junisean@naver.com이야. 플랫폼이 보증하는 사용자 ID·이메일을 서버에서 검사해. 임의 클라이언트 플래그나 공개된 비밀번호로 관리자를 판별하지 마. 공개 접속과 관리자 데이터 조회 권한을 분리해.
/admin에는 설문 만들기 복귀 링크, 제출된 답변 제목, 지원자 목록과 더 보기를 넣어. 목록에는 이름, 서울 시간 기준 제출 일시, 미확인·확인함 상태를 표시해. 각 지원자를 펼치면 생년월일, 전화번호, 모든 원본 질문과 답변을 볼 수 있어야 해. 직접 질문도 포함해.
지원자를 펼쳤을 때 확인 상태를 서버에 저장하고 성공하면 확인함으로 바꿔. 목록을 불러오기만 했을 때는 확인 처리하지 마. 확인 정보는 reviewed/{id}.json에 별도로 저장하고 원본 지원서를 바꾸지 마. 저장 실패 안내와 재시도를 지원해.
목록은 20건씩 커서 페이지네이션해. 빈 목록·로딩·오류 상태를 구현해. 미확인 건수는 전체 저장 자료 기준으로 집계해. 첫 페이지 진입과 창 복귀 시 배지를 갱신해.
POST /api/submissions, GET /api/submissions?cursor=, GET /api/submissions/summary, PATCH /api/submissions/{id}, GET /admin을 PRD대로 구현해. 목록·집계·확인 처리 모두 서버에서 관리자 권한을 검사해. 쓰기 요청은 동일 출처를 검사하고 입력·본문 크기 검증을 제공해. 응답 데이터는 캐시하지 마. 사용자 입력은 텍스트로 렌더링해.

운영
운영 첫 페이지는 공개 접속이 가능해야 하고, 설문 링크를 받은 지원자는 별도의 관리자 권한 없이 작성·제출할 수 있어야 해. 응답과 개인정보의 조회는 사장님만 가능해야 해.
현재 운영 주소는 https://table-team-survey-1105.junisean.chatgpt.site/ 이고 단축 링크 https://is.gd/bestmember 는 이 첫 페이지로 이동해. 단축 링크와 지원자 설문별 전용 링크를 혼동하지 마. 다른 환경으로 복제한다면 동일 단축 주소를 무단으로 덮어쓸 수 있다고 가정하지 말고 새 배포 주소를 정확히 알려줘.
기존 Sites에서 작업하면 프로젝트 ID appgprj_6aeb524514dc8191a125aa278a3df937와 BUCKET 바인딩을 유지해. 서버 기능을 정적 HTML 배포만으로 대체하지 마.

완료 조건
PRD 16장의 모든 검증 항목을 확인해. 특히 기본 질문 총 10개 제한, 직접 질문 별도 추가, 전용 링크 복원, 지원자 전용 화면, 필수 입력 검증, 실제 서버 영속 저장, 재시도와 중복 방지, 관리자 외 조회 차단, 확인 상태 영속 저장, 전체 미확인 집계, 공개 접속을 검사해.
자동 채점, 합격 판정, 점수, 객관식, 자동 메시지 발송 등 요청하지 않은 기능을 필수 동작 대신 만들지 마. 화면만 구현하고 서버는 나중에 하겠다고 끝내지 마.
첨부 소스가 없거나 문항 원본에 접근할 수 없다면 질문이나 데이터를 지어내지 말고 필요한 첨부 자료를 정확히 알려줘. 이 ZIP에 포함된 전체 소스와 원본을 먼저 찾아 사용해.
